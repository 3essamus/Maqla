## 🎯 Overview

### Vision
Transform the current restaurant management app into **Maqla** - a public restaurant discovery hub for Jijel where:
- **Buyers** can browse restaurants anonymously and order via WhatsApp
- **Restaurant Owners** can manage their presence with tier-based plans
- **Admins** can manage the platform and generate activation keys

### Key Differentiators
- ✅ **Anonymous browsing** - No login required for buyers
- ✅ **WhatsApp-first** - Orders placed directly via WhatsApp (no in-app checkout)
- ✅ **Subscription model** - Key-based activation (Free/Paid tiers)
- ✅ **Community-driven** - Anonymous buyer reviews with admin moderation
- ✅ **Local-first** - French language, DZD pricing, Jijel-focused

## 🚀 New Features & Changes

### 1. **Role-Based Access Control**
| Role | Permissions |
|------|-------------|
| **Admin** | Generate keys, view all restaurants, moderate reviews, manage users |
| **User (Free)** | 1 restaurant, 3 menus, 5 menu items total |
| **User (Paid)** | 1 restaurant, unlimited menus, unlimited items |
| **Buyer (Anonymous)** | Browse restaurants, add to cart, order via WhatsApp, leave reviews |

### 2. **Subscription & Key System**
- **Free Tier**: Default (5 items max)
- **Paid Tier**: 5,000 DZD/year (unlimited items)
- **Key Activation**: Single-use keys generated by admin
- **Expiration**: Keys expire 1 year after activation
- **Renewal**: Users request new keys from settings

### 3. **Public Explore Homepage**
- Move `/explore` to `/` (homepage)
- No authentication required
- Grid/List view of published restaurants
- Search & filter functionality
- Restaurant cards with:
  - Logo, name, location
  - Delivery fee badge
  - Rating display
  - "View Menu" CTA

### 4. **Cart & WhatsApp Ordering**
- **Cart Toggle**: Buyers can enable/disable cart
- **Cart Storage**: LocalStorage (anonymous)
- **Cart Display**: Floating button with item count
- **Order via WhatsApp**:
  - Generates formatted message
  - Includes: restaurant name, items, quantities, total, delivery fee
  - Pre-fills WhatsApp with restaurant's contact number
  - Opens WhatsApp web/app with message

### 5. **Review System**
- **Who**: Anonymous buyers (no login)
- **What**: Name (text), rating (1-5 stars), comment (text)
- **Spam Prevention**:
  - Browser fingerprinting (localStorage tracking)
  - Rate limiting (1 review per restaurant per browser)
  - Admin moderation queue
- **Admin Actions**: Hide/remove reported/spam reviews
- **Display**: Show on restaurant page with average rating

### 6. **Restaurant Profile Enhancements**
- **WhatsApp Number**: Required field (used for orders)
- **Delivery Fee**: Optional field (e.g., 200 DZD)
- **Published Status**: Must be published to appear in explore

### 7. **Admin Panel**
- **Key Management**:
  - Generate activation keys
  - View key status (unused/used/expired)
  - Assign keys to specific tiers
- **Restaurant Moderation**: View all restaurants, unpublish if needed
- **Review Moderation**: Hide/remove flagged reviews
- **User Management**: View users, tier status, expiration dates

### 8. **French Localization**
- All UI text in French
- Currency: DZD (Dinar Algérien)
- Date format: DD/MM/YYYY
- Number format: French locale

### 9. **Design System Refresh**
- New color palette (TBD - Mediterranean/Jijel-inspired?)
- Updated typography (modern, readable)
- Maintain current component structure
- Improve mobile responsiveness

## 🗄️ Database Schema Changes

### New Models

```prisma
// Add to schema.prisma

model User {
  id            String    @id @default(cuid())
  email         String    @unique
  name          String?
  image         String?
  role          UserRole  @default(USER)
  tier          UserTier  @default(FREE)
  tierExpiresAt DateTime?
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt

  restaurants   Restaurant[]
  activatedKeys ActivationKey[]

  @@index([email])
}

enum UserRole {
  ADMIN
  USER
}

enum UserTier {
  FREE
  PAID
}

model ActivationKey {
  id         String          @id @default(cuid())
  key        String          @unique @default(cuid())
  tier       UserTier
  expiresAt  DateTime        // 1 year from generation
  status     KeyStatus       @default(UNUSED)

  userId     String?
  user       User?           @relation(fields: [userId], references: [id])

  activatedAt DateTime?
  createdAt   DateTime       @default(now())
  createdBy   String         // Admin user ID

  @@index([key])
  @@index([status])
}

enum KeyStatus {
  UNUSED
  USED
  EXPIRED
}

model Review {
  id           String        @id @default(cuid())
  restaurantId String
  restaurant   Restaurant    @relation(fields: [restaurantId, restaurantUserId], references: [id, userId])
  restaurantUserId String     // For composite key

  buyerName    String
  rating       Int           // 1-5
  comment      String

  fingerprint  String        // Browser fingerprint for spam prevention
  isHidden     Boolean       @default(false)

  createdAt    DateTime      @default(now())
  updatedAt    DateTime      @updatedAt

  @@index([restaurantId])
  @@index([fingerprint])
  @@unique([restaurantId, fingerprint]) // Prevent duplicate reviews
}
```

const user = await ctx.prisma.user.findUnique({
  where: { id: ctx.session.user.id },

if (user.tier === 'FREE') {

    .flatMap(r => r.menus)
    .flatMap(m => m.categories)

### Step 13: Implement WhatsApp Order Flow

**New File**: `/src/utils/whatsapp.ts`

**Function**: `generateWhatsAppMessage`
```typescript
interface OrderDetails {
  restaurantName: string;
  items: { name: string; quantity: number; price: number }[];
  deliveryFee: number;
  total: number;
}

function generateWhatsAppMessage(order: OrderDetails): string {
  const itemsList = order.items
    .map(item => `- ${item.name} x${item.quantity} (${item.price * item.quantity} DZD)`)
    .join('\n');

  return `
🍴 Nouvelle commande de ${order.restaurantName}

📋 Articles:
${itemsList}

💰 Sous-total: ${order.total - order.deliveryFee} DZD
🚚 Livraison: ${order.deliveryFee} DZD
✅ Total: ${order.total} DZD

Merci!
  `.trim();
}

function openWhatsApp(phoneNumber: string, message: string) {
  const encodedMessage = encodeURIComponent(message);
  const url = `https://wa.me/${phoneNumber}?text=${encodedMessage}`;
  window.open(url, '_blank');
}
```

function generateFingerprint(): string {
  const data = [
    navigator.userAgent,
    navigator.language,
    screen.width,
    screen.height,
    new Date().getTimezoneOffset(),

}

## 📝 Notes & Considerations

### Security
- **Key Security**: Activation keys should be cryptographically random (use `cuid()` or `nanoid()`)
- **Rate Limiting**: Implement rate limiting on review submission and key activation
- **CSRF Protection**: NextAuth handles this, but verify for custom forms
- **SQL Injection**: Prisma provides protection, but validate all inputs
- **XSS**: Sanitize user-generated content (review comments)

### Performance
- **Image Optimization**: Already using ImageKit + blurhash ✅
- **Static Generation**: Use SSG for public menu pages ✅
- **Code Splitting**: Next.js handles this automatically ✅
- **Database Indexing**: Add indexes on frequently queried fields (restaurantId, userId, fingerprint)
- **Caching**: Consider caching explore page results (SWR or React Query)

### Scalability
- **Database**: PostgreSQL can handle thousands of restaurants
- **Image Storage**: ImageKit handles CDN and optimization
- **Serverless**: Vercel functions scale automatically
- **Future**: If traffic grows, consider:
  - Redis for session storage
  - ElasticSearch for restaurant search
  - Separate admin and public apps

### Legal & Compliance
- [ ] Update Privacy Policy (mention fingerprinting for reviews)
- [ ] Update Terms & Conditions (subscription terms, refund policy)
- [ ] Add GDPR compliance if targeting EU users
- [ ] Consider Algerian data protection laws

### Future Enhancements (Post-MVP)

- **Email notifications**: Order confirmations, key expiration reminders
- **SMS integration**: Order updates via SMS
- **Advanced analytics**: Restaurant dashboard with insights
